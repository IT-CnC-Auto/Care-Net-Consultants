## 4. Server (Vercel functions, portable Node, no npm dependencies; CommonJS `module.exports = async (req, res) => {}` like vercel/api/intake.js)

- `vercel/lib/auth.js`: `async function requireUser(req)` reads `Authorization: Bearer <access_token>`, calls `GET ${SUPABASE_URL}/auth/v1/user` with headers apikey = SUPABASE_SERVICE_ROLE_KEY and Authorization = the user token, returns `{id, email}` or throws an error with `.status = 401`. `function sendError(res, err)` maps .status.
- `vercel/api/hsf-consent.js`: GET → hsf_consent_status; POST `{kinds: [...], wording_version}` → hsf_record_consent; DELETE `?kind=` → hsf_withdraw_consent.
- `vercel/api/hsf-upload.js`: POST `{action: 'register', ...register input}` → hsf_register_upload, then `POST ${SUPABASE_URL}/storage/v1/object/upload/sign/hsf-staging/<path>` (service role) → returns `{upload_id, upload_url}` where upload_url = `${SUPABASE_URL}/storage/v1` + returned `url` (it carries the token). Browser then `PUT upload_url` with the file body and header `Content-Type`. POST `{action: 'complete', upload_id}` → hsf_mark_uploaded. GET `?file_id=` → hsf_my_uploads.
- `vercel/api/hsf-file.js`: GET → hsf_my_files; GET `?file_id=` → hsf_file_detail; POST `{action: 'generate', ...}` → hsf_generate_file; POST `{action: 'set_status', item_id, status, reason}` → hsf_set_item_status.
- `vercel/api/kernel.js`: public read API for the Grok bot and other approved clients. `GET /api/kernel?r=industries|industry|instruments|protocols|elements|search&code=&industry=&q=`. Auth header `Authorization: Bearer cnck_...`; sha256 in Node crypto; msp_api_authorise; 401 on bad key, 429 on rate limit, 400 on bad resource. JSON only; `Cache-Control: no-store`; CORS `Access-Control-Allow-Origin: *` with `Authorization` allowed (keys are server to server; no cookies).
- `server/serve.js`: dependency free Node http server that serves `vercel/` statics (cleanUrls like vercel.json) and mounts every `vercel/api/*.js` handler at `/api/<name>`, adding `req.query` and a parsed JSON `req.body` and `res.status().json()` helpers. This is the path to hosting inside MCO.
- Tests: `test/api/*.test.js` runnable with `node --test`, mocking global fetch.

## 5. MCO transfer worker

- `supabase/functions/_shared/mco-adapter.js` (plain ES module, no Deno or Node specific APIs; uses global fetch and crypto.subtle): `export async function sha256Hex(bytes)`, `export function createAdapter({mode, baseUrl, token})` returning `{ send({uploadId, fileName, mimeType, bytes, sha256, clientAccountId, departmentCode, sectionCode}) }` → `{outcome: 'held'|'received'|'error', mcoDocumentRef, receiptSha256, error}`. mode hold → held, no network. mode fixture → received with ref 'FIXTURE-' + uploadId and receiptSha256 = sha256 (for tests only). mode live → throws 'MCO interface contract pending (HSF-3)' unless baseUrl and token set; the live request shape is a documented placeholder and must not be presented as a real MCO endpoint.
- `supabase/functions/hsf-mco-transfer/index.ts` (Deno, Supabase edge function, invoked by schedule or manually with the service role): reads `hsf.mco_transfer_mode`, calls hsf_transfer_queue(10), downloads each object, computes sha256Hex, sends, calls hsf_transfer_record, and only on outcome received with matching hashes deletes the object (`DELETE /storage/v1/object/hsf-staging` with `{prefixes:[path]}`) and then calls hsf_mark_staging_deleted. Never deletes on held, error or mismatch.
- `test/mco/adapter.test.mjs` with `node --test` for hold and fixture paths and the hash check.
