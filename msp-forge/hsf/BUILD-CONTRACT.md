9.3 **File citations.** An instrument is citable **for a File element** only when it is verified, not held, not superseded, its `scope` is 'safety' or 'both', and the element's `hsf_element_instrument.provision` is not 'awaiting verification'. 10.4 **Every upload is scanned before it can move.** New columns on hsf_upload: `scan_status text not null default 'pending' check in ('pending','clean','infected','harmful','error')`, `scan_engine text`, `scanned_at timestamptz`, `scan_findings jsonb`. Rules:
- `hsf_transfer_claim` returns only rows with `scan_status = 'clean'`. In hold mode a clean upload still becomes held as today.
- `hsf_scan_claim(p_limit int) returns setof hsf_upload` (service role): uploads in status 'uploaded' with scan_status 'pending' or 'error' (error retried, at most 5 attempts tracked in a new column `scan_attempts int not null default 0`), not blocked, bytes present, `for update skip locked`, oldest first; increments scan_attempts.
- `hsf_scan_record(p_upload_id uuid, p_result text, p_engine text, p_findings jsonb) returns jsonb` (service role): p_result in ('clean','infected','harmful','error'). infected or harmful → status 'rejected', reject_reason 'The file failed the security scan: <plain summary from findings>', evidence revoked as in the hash mismatch path, audit `hsf_upload_scan_rejected`; the bytes then leave through the existing cleanup queue (rejected rows are already listed there). clean → scan_status clean. error → scan_status error, stays uploaded.
- Worker: new module `supabase/functions/_shared/scan-core.js` (plain ES module, no dependencies, global fetch and crypto.subtle only) exporting `inspectBytes({bytes, mimeType, fileName}) → {verdict: 'clean'|'harmful', findings: [{code, message}]}` and `createAvEngine({endpoint, token, fetch})` and `scanUpload(row, deps)`. inspectBytes, the built in structural check, always runs and flags as harmful: content whose magic bytes do not match the declared type (PDF `%PDF-`, PNG, JPEG, OOXML zip `PK\x03\x04`, legacy Office OLE `D0 CF 11 E0`, CSV must be valid UTF 8 text without NUL bytes); PDF containing `/JavaScript`, `/JS`, `/Launch`, `/OpenAction` with JavaScript, `/EmbeddedFile`, `/RichMedia`, `/XFA`, or `/AA`; OOXML containing `vbaProject.bin`, `activeX`, `oleObject` embeddings or relationships with `TargetMode="External"` (read the zip central directory and the `_rels/*.rels` and `word/_rels`/`xl/_rels` entries; stored and deflated entries, deflate via `DecompressionStream('deflate-raw')` where available, otherwise flag 'could not inspect' as error, not clean); legacy Office files containing a `Macros` or `_VBA_PROJECT` stream name or the bytes `VBA`/`Attribute VB_` (flag as harmful: macros); CSV cells beginning with `=`, `+`, `-`, `@`, tab or carriage return followed by formula like content (formula injection); JPEG or PNG carrying EXIF GPS tags (location metadata) or oversized metadata segments over 256 KB. Findings carry plain words for the client. `createAvEngine`: HTTP antivirus engine at `HSF_AV_ENDPOINT` (env; for example a ClamAV REST service hosted by Care Net or MCO), bearer `HSF_AV_TOKEN`; request `POST <endpoint>` with the raw bytes, `Content-Type: application/octet-stream`, header `X-File-Name`; expected reply `{clean: boolean, signature: string|null, engine: string}`. The engine is mandatory: with no endpoint configured the scan records `error` with finding 'Antivirus engine not configured' and the file never transfers. Only the test environment variable `HSF_SCAN_ALLOW_FIXTURE=1` permits a fixture engine that answers clean (never set in production). Order in `runTransfer`: mode, sweep, scan pass (`hsf_scan_claim(10)` → download → sha256 must equal sha256_server else record error → inspectBytes → AV engine → hsf_scan_record), then transfer claim, then cleanup, then retention. One document in memory at a time.
- The builder shows the scan state: 'Security scan pending', 'Passed security scan', 'Failed security scan: <reason>'.
